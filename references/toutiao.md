# 今日头条 / Toutiao (s_toutiao.py)

> 今日头条**文字内容**抓取：**搜索 / 文章正文 / 微头条 / 评论 / 热榜**。
> 走页面 SSR 内嵌数据解析，**零凭证**（不需要 cookie / 登录 / API Key / 签名），纯 Python 标准库。
> 脚本：`scripts/s_toutiao.py`（2026-09-10 实测 13/13 通过）
> **定位：专精文字内容。视频已放弃**（技术上不可行，详见「视频内容」章节）。
>
> ⚠️ **最高频踩坑：移动版域名必须用 iPhone UA**。桌面 UA 会被 302 跳到 `www` 版（JS 空壳，正文 0 字）。详见下方「UA 是唯一的开关」章节。

## 为什么自建脚本（而不是用现成工具）

调研结论（2026-09-10，GitHub REST API 实时取证）：

| 方案 | 为什么不可用 |
|---|---|
| 旧公开 API `www.toutiao.com/api/search/content/` | 已废弃，返回 `count:0` |
| 旧评论 API `/api/comment/list/`、`/2/comment/list/` | 500 / 404，全部失效 |
| **RSSHub**（`/toutiao/*`） | 只有频道流和作者主页，**没有关键词搜索**；公共实例 403，需自建 Docker |
| **Firecrawl / better-webfetch** | 桌面版是 JS 空壳（"需要允许执行 JavaScript"）；Firecrawl 抓文章页持续 500 |
| 各类 `*-mcp` 项目 | 除热搜类外全是「发文运营」工具，需浏览器 + 登录，且多为无 License 的休眠仓库 |
| 高星 `iMeiji/Toutiao` 等 | 是「仿头条 App 的客户端 UI 项目」，与抓取无关（按 star 排序会严重误判） |

**真相**：头条把搜索结果和正文都内嵌在页面的 SSR 数据里，用对 UA 直接解析即可 —— 无需破解签名。

## UA 是唯一的开关（最重要的机制）

实测对照（同一 URL，只改 UA）：

| UA | `m.toutiao.com/article/{id}/` 结果 |
|---|---|
| 无 UA / 桌面 Chrome | **302 跳转** → `www.toutiao.com/...`，正文 **0 字** |
| **iPhone Safari** | 200 保持移动版，正文 **1786 字** ✅ |
| Android Chrome | 200 保持移动版，正文 **1787 字** ✅ |

- 服务端读 UA 做设备自适应：移动 UA → 移动版页面（**正文内嵌在 SSR 里**）；桌面 UA → 跳 www 版（JS 运行时渲染，抓不到）。
- **不是写死域名**，也没绕任何防护 —— 就是用移动端身份请求。
- **Referer 不是必需**（实测带不带结果一致），脚本里带上更保险。
- 脚本已内置 `UA_M`（iPhone），**勿改成桌面 UA**，否则正文全丢。

## 数据在页面里的位置（解析要点）

| 内容 | 位置 | 备注 |
|---|---|---|
| 搜索结果 | `<script data-druid-card-data-id="...">{JSON}</script>` | 每张卡片一条；跳过 `template_key` 为 `SearchBar`/`BottomBar` 的框架卡片 |
| 文章正文 | `<script id="RENDER_DATA">` → URL 解码 → `articleInfo.content` | HTML 片段，剥标签得纯文本 |
| **微头条正文** | 同上 → `articleInfo.thread.threadBase.content` | ⚠️ **路径不同**，微头条没有 `articleInfo.content` |
| 评论 | `data[i].comment` | **嵌套一层**，不是 `data[i]` 直接就是评论 |
| 评论用户名 | `comment.user_name` | ⚠️ 不在 `comment.user.screen_name`（那是详情接口的字段） |

## 需要特殊处理的坑（脚本已处理，改代码时注意）

1. **搜索偶发"空手"（约 5%，与频率无关）**：随机出现无卡片页面（HTML 长度骤降到 ~210KB）。
   ⚠️ **这是随机抖动，不是限速** —— 压测证明连续快速请求成功率 **100%**，反而是慢速间隔偶尔触发（见下方「请求频率实测」）。
   脚本内建 3 次重试以覆盖。
   ⚠️ **不要用 HTML 长度做判据** —— 视频页 224KB、空手响应 210KB，太接近会误伤。只认「解析出的卡片数」。
2. **微头条 title 字段 = 正文本身**：直接输出会导致标题和正文重复。脚本做了首行截断去重。
3. **媒体号文章的 `article_url` 指向外站**（mp.weixin.qq.com / peopleapp.com 等）。脚本主链接一律用**官方 group 形态**（`toutiao.com/group/{gid}/`），外链单列 `ext_url`。
   ⚠️ **绝不要自己拼 `/article/{gid}/` 或 `/w/{gid}/`** —— 实测这些形态在桌面和安卓下都是反爬挑战页。详见「🔗 链接形态」章节。
4. **`sslocal://` 是 App 内部 scheme**，网页打不开，脚本已过滤。
5. **视频卡片结构完全不同**：`display` 是 **dict 不是 list**，标题在 `display.title` / `display.emphasized.title`，摘要字段可能是纯数字编码串（需过滤）。站外视频 id 为**负数**，不能拼站内链接。
6. **回复不在主接口里**：`reply_list` / `new_reply_list` 内嵌字段常为空数组，即使 `reply_count > 0`。必须两段式：先取 `comment.id_str` → 再调 `reply_list`。
7. **评论 ID vs 内容 ID 是两回事**：主接口内容 ID 叫 `group_id`，评论 ID 是 `comment.id_str`，别搞混。
8. **代理会污染请求**：脚本已在导入时清空 `HTTP_PROXY` / `HTTPS_PROXY`（本机已知坑：裸调会被拼进请求路径导致 404）。
9. **请求间隔**：脚本内置 0.5–1.5 秒间隔，勿去掉，否则容易触发风控。

## 视频内容：❌ 已放弃（技术不可行）

**结论：今日头条的视频搜索/抓取，本工具不支持，也不建议尝试。**

穷尽验证记录（2026-09-10）：

| 尝试的路径 | 结果 |
|---|---|
| `yt-dlp`（v2026.03.17，内置 `toutiao` extractor） | ❌ `No video formats found!` |
| `m.toutiao.com/video/{gid}/` 页面 | 200 但**无视频流 URL**；仅 `playUrlList: null` + `playAuthTokenV2`（JWE 加密令牌） |
| 播放 API（6 种端点形态实测） | ❌ 404 / 504 |
| 页面 JS 里的播放接口 | 只有 `/short_play`，拿不到流地址 |
| `pd=video` 搜索返回内容 | **几乎全是站外链接**（实测全是哔哩哔哩），头条自建视频池不对外开放 |

**根因**：头条原生视频 ≈ 抖音系内容（实测 `bizTag=小视频`、`groupSource=19`），视频流需**登录态 + `playAuthTokenV2` 签名换取**，页面 SSR 不含明文地址。属抖音系防护范畴，不在本工具射程内。

**要抓视频内容怎么办**：直接去视频所在的**原始平台**取，不要绕道头条。

- 站外视频（B站/YouTube 等）→ 用 `references/video.md` 的 `transcribe.py` / `bili` / `yt-dlp`
- 抖音系视频 → 防护严格，同属不可行

> 脚本已**移除 `--type video` 选项** —— 不提供做不到的能力，避免误用。头条渠道的定位就是**文字内容**（图文 + 微头条 + 评论 + 热榜）。

## 评论抓取的现实提醒

⚠️ **媒体机构号的文章评论数普遍很低甚至为 0**（实测多篇 `total_number=0`）。
评论多的主要是**自媒体 / 个人号**内容，尤其**财经、股市、楼市**类。

→ 如果用评论做舆论分析，**优先抓微头条和自媒体内容**（实测一条股市微头条有 29 条评论）。

**计数一致性已交叉验证**（页面标注 vs 接口 `total_number`，4 篇全部吻合）：15→15 · 8→8 · 6→6 · 16→16。

## 🧹 评论数据质量：三类噪声必须先清洗（2026-09-11 实证）

做舆情分析时，评论原始数据里有三类东西必须处理，否则结论会失真：

### ① 系统占位文本 —— 直接剔除

内容恒为 `图片评论，在最新版今日头条app中可查看`（用户发了图、网页端不可见的遗留提示）。
实测一次抓取中占 **46/1231 = 3.7%**，且会占据高赞位（见过 17 赞的占位文本）。**它不是观点**，计入会虚增评论量、稀释情绪比例。

```python
PLACEHOLDER = re.compile(r'^图片评论[，,]在最新版今日头条app中可查看$')
real = [c for c in items if not PLACEHOLDER.match(norm(c['text']))]
```

### ② 去重要按 `comment_id`，**不要按文本**

反直觉但重要：**同一段文本被不同账号发布 = 不同人的发言，有分析价值，不能合并。**

```python
# ✅ 正确：按 comment_id 去重
byid = {c['comment_id']: c for c in items}
# ❌ 错误：按文本去重会抹掉"多人发同样内容"这一关键信号
```

### ③ 疑似协同发帖 —— 这是最有价值的发现

判定标准（可复用）：**同一段文本被 ≥3 个不同账号发布，且最高赞 < 20**。
对照组：同为多账号发布的自然流行梗（如 `老乡别走[捂脸]` 有 136 赞）→ 不计入。

实测命中 7 组、32 条，特征高度一致：
- 文本口语化、中性偏正面、给政策留余地（`还需要时间去验证`/`先观望更稳妥`）
- **全部 0 赞**（发出来无人认同）
- **75% 集中在同一个帖子**

典型样本：

| 重复文本 | 账号数 | 最高赞 |
|---|---|---|
| 现在抄底说不定还跌，先观望更稳妥 | 6 | 0 |
| 政策规划归规划，实际行情可能不按走 | 5 | 0 |
| 市场长期生态建设，还需要时间去验证 | 4 | 0 |
| 国家队终于进场了👍 | 3 | 0 |
| A股利好太给力啦👏 | 3 | 0 |

**这是「页面标注的评论数 ≠ 真实公众关注度」的硬证据。** 做热度排序/舆论量级判断时，必须把协同样本标出来并说明，否则会把「内容投放」误当成「公众关心」。

## ⏰ 评论时间归属：累计池 ≠ 当日增量（2026-09-11 实证踩坑）

**头条评论接口返回的是「累计池」，不是「当日新增」。** 直接拿 `total_number` 当作当日舆情量级是错的。

→ 必须按每条评论的 `create_time` **切分到目标时间窗口**，再统计窗口内的量。
→ 与小红书 `--all` 的「头部截面」问题同类（见 agent-reach/references/xiaohongshu.md ②-d）：**任何评论区舆情，先按时间过滤再排序，不要先排序再过滤。**

## 🔗 链接形态：必须用官方 group 形态（重要）

**给人点击的链接一律用** `https://toutiao.com/group/{gid}/`

这是头条搜索结果卡片里**官方提供的**分享链接（字段：`ttsearch_msite_url` / `item_source_url` / `seo_url`，本工具取去掉追踪参数后的干净形态）。它的特性：

**会按访问设备自动派发**（服务端读访问者 UA，与抓取时的 UA 无关）：

| 访问设备 | `toutiao.com/group/{gid}/` 的表现 |
|---|---|
| 安卓 / iPhone | ✅ 自动跳 `m.toutiao.com`，**SSR 真内容**（含 `RENDER_DATA`） |
| 桌面 Chrome | 文章类 → 跳到媒体原站（如 peopleapp.com，可读）；微头条类 → 网页版 |

### ❌ 不要自己拼这两种形态（实测失败）

| 自己拼的形态 | 桌面 | 安卓 | iPhone |
|---|---|---|---|
| `www.toutiao.com/article/{gid}/` | ❌ 反爬挑战页 | ❌ 反爬挑战页 | ❌ 挑战页 |
| `www.toutiao.com/w/{gid}/` | ❌ 反爬挑战页 | ❌ 反爬挑战页 | ❌ 挑战页 |

「挑战页」= HTTP 200 但返回 **72914 字节的 JS 反爬壳**（`_$jsvmprt` 虚拟机），无任何内容 —— 看字节数就能识别。

> **教训（2026-09-11 修复）**：本工具早期版本的 `_native_url()` 自己拼 `/article/` 和 `/w/`，实测在桌面**和**安卓下都是挑战页，等于**链接全是坏的**。改为官方 `group` 形态后修复。
> 根因：**应该用数据源自己提供的链接字段，而不是自己推断 URL 规则**。

### 关于 UA（澄清一个常见误解）

- **抓取时的 iPhone UA 与链接无关**。UA 是请求头，随每次 HTTP 请求走；HTML 里的链接只是纯文本 URL。
- 链接打开时用的是**访问者自己浏览器的 UA** —— 所以不存在"因为抓取用了 iPhone UA，链接在电脑上就打不开"这回事。
- 真正决定能否打开的是**链接形态**（group ✅ vs 自拼 ❌）。

### 各端现实表现

| 端 | 体验 |
|---|---|
| 安卓 / iPhone | ✅ 最好，自动进移动版，内容完整 |
| 桌面浏览器 | ⚠️ 一般 —— 文章跳媒体原站，微头条是网页版/可能出挑战页。这是头条自己的策略，非链接问题 |

**写报告时的建议**：链接直接用官方 group 形态即可，无需特殊处理。若报告主要给电脑看，可同时附上「原文」外链（本工具输出的 `ext_url` 字段）作为兜底。

## 请求频率实测（2026-09-10，104 次请求压测）

| 压测项 | 结果 | 耗时 |
|---|---|---|
| 搜索接口 连续 30 次（**零间隔**） | **30/30 = 100%** | 21.8s |
| 搜索接口 交替关键词 20 次（零间隔） | 19/20 = 95% | 15.1s |
| 评论接口 连续 15 次（零间隔） | **15/15 = 100%** | 5.4s |
| 热榜接口 连续 15 次（零间隔） | **15/15 = 100%** | 2.5s |
| 混合端点 24 次（零间隔） | **24/24 = 100%** | 9.8s |
| **合计 104 次** | **103/104 = 99%** | — |

### 关键发现：那个"偶发空手"不是限速

早期我在不同间隔下做过对照，结果很反直觉：

| 请求间隔 | 成功率 |
|---|---|
| 0s（极限连打） | **100%** |
| 0.5s | 88% |
| 1s / 2s / 3s | 100% |

**结论**：偶尔出现的"空手"（无卡片、HTML 骤降到 ~210KB）是**随机抖动**，与请求频率**无关** —— 快速连打反而全通。因此：

- ✅ **不需要刻意降频/加冷却**，正常用即可（单次请求约 0.7s）
- ✅ 脚本内建 3 次重试已足以覆盖那 ~5% 的随机抖动
- ❌ 不要为了"防封"而人为加长间隔 —— 没有收益，反而不必要的慢

> 实测成本：完成上述 104 次压测仅约 55 秒。日常使用场景（搜几次+读几篇）对服务器压力可忽略。

### 唯一建议

不要做**极端高频的无意义轮询**（如死循环刷同一关键词）—— 这是对任何网站的通用礼貌，不是头条特有的限制。
如需监控某关键词变化，用 `cron` 定时（分钟级）而非秒级轮询。

## 凭证存放位置

**无凭证**（2026-09-10 实测确认）：搜索、正文、评论、热榜四个能力**全部免登录**，不需要 cookie / token / API Key。
脚本不读取任何凭证文件，不产生登录态。

## 账号管理（读前必看 ⚠️）

**技术可行性**：头条号后台 `mp.toutiao.com` 是纯 JSON API（已从前端 JS 逆向出 **111 个 `/mp/agw/*` 端点**），匿名访问统一返回 `{"code":100004,"message":"user not login"}` —— **有合法 cookie 就能纯 HTTP 读写，无需 Selenium**。

**官方途径**：

| 路径 | 能做到 | 门槛 |
|---|---|---|
| 「内容源接入」RSS 同步（后台→工具） | 自建 RSS 源 → 头条自动发表图文 | 需自有站点；**只能发，无数据回读** |
| 抖音开放平台 open.douyin.com | 发布**视频**到头条 + 读视频数据 | **需企业/机构资质**，个人主体走不通 |

**风险提示（务必遵守）**：

- 头条号协议**明文禁止**模拟登录 / 自动化脚本操作后台
- 头条号 100 分信用分制度，违规可扣分至封号
- 同类实证：小红书 2026-03-10 官方公告「对通过 AI 托管工具完成注册、发布、互动的账号予以封禁」；`xiaohongshu-mcp` 有用户反馈两个账号因机械化发布被封。**字节系风控同源。**
- **cookie 泄露 = 后台被接管**

**建议**：如确需账号管理，**先做只读**（用自己的 cookie 拉内容列表/数据做分析，无副作用），写操作走官方 RSS 或严格限频。**绝不要**把账号密码交给第三方在线服务，**绝不要**做多账号矩阵式自动化。

> 本项目**不包含**账号管理脚本 —— 这是有意的设计选择。

## 已知坑

- **桌面 UA 抓不到正文**：必须 iPhone UA（见「UA 是唯一的开关」）。这是最容易踩的坑。
- **微头条正文路径不同**：`articleInfo.thread.threadBase.content`，不是 `articleInfo.content`。
- **评论嵌套一层**：`data[i].comment.text`。
- **评论回复需两段式**：见坑 #6。
- **搜索翻页无效**：`offset` 参数被忽略，SSR 只出首页 10 条。要更多结果就换关键词或用 `filter_period`。
- **视频卡片结构差异**（保留为解析知识）：部分卡片 `display` 是 dict 而非 list，标题在 `display.title` / `display.emphasized.title`，摘要字段可能是纯数字编码串（需过滤）。站外内容 id 为**负数**，不能拼站内链接。
- **内容 ID 正负号**：站内 ID 为正，站外 ID 为负（拼接链接前需判断）。
